## Roadmap Design Guide

### 1. Core Teaching Philosophy

- **Interactive First:** Every concept must be taught through action. Theory is minimal.
- **Project-Based Milestones:** Every module MUST end with a small, tangible project that uses all the concepts from that module. This is non-negotiable.
- **Purpose-Driven Narrative**: Frame the learning journey around professional growth and capability. The learner is a an inspired future software engineer. Titles must be engaging by using strong, relatable analogies.
- **Gentle Learning Curve:** No large difficulty spikes. Each lesson (item) should introduce only ONE major new concept.
- **Competence & Mastery:** Users feel smart and capable after every short session, thanks to a gentle learning curve and constant positive feedback.

### 2. Structure & Pacing

- **Module Size:** A module should contain 3-6 lessons (items).
- **Lesson Size:** A lesson (item) should be completable in 5-10 minutes.
- **Roadmap Structure:** The first module is always the absolute basics. The final module is always a significant capstone project that ties everything together.

### 3. Naming & Language

- **Thematic Tone**: The tone must be professional, empowering, and related to the module topic. It should respect the learner as an intelligent adult aiming to build skills. Avoid whimsical, childish, or overly abstract themes.
- **Clarity Over Jargon:** While we teach technical terms, the goals and descriptions should be in plain, simple language that a beginner can understand. And introduce technical terms slowly one by one.

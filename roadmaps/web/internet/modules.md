### **Track: How the Internet Works**

**Track Goal:** To demystify the internet for absolute beginners using simple analogies. This is a non-coding, conceptual track that builds a mental model for how users access websites, preparing them for web development topics.

---

### **Module 1: What is the Internet, Really?**

- **Core Question Answered:** "I use the internet every day, but what is it?"
- **Concepts:** The internet as a global network of connected computers. The idea of "The Cloud" being just someone else's computer. Physical infrastructure (undersea cables, data centers).
- **Key Analogy:** A giant, global postal system for digital information, with roads (cables) connecting all the houses (computers).
- **Difficulty:** Easy
- **Importance Score:** 9/10
- **Questions to Answer:**
  - In one sentence, what is the internet?
  - When you upload a file to "the cloud," where is that file actually being stored?
  - Is the internet a purely wireless system, or does it depend on physical connections?

### **Module 2: Your Digital Address (IP & Domains)**

- **Core Question Answered:** "What's the difference between `akood.com` and a bunch of numbers like `192.168.1.1`?"
- **Concepts:** Introduction to IP addresses as unique identifiers for every device. Introduction to Domain Names as human-friendly labels for those addresses. Fast look into IPv4.
- **Key Analogy:** An IP address is like a specific street address (e.g., 123 Main Street, Anytown). A Domain Name is like the name of the place at that address (e.g., "The Grand Library").
- **Difficulty:** Easy
- **Importance Score:** 10/10
- **Questions to Answer:**
  - What is the main purpose of an IP address?
  - Why do we need domain names if computers use IP addresses?
  - What is the relationship between a domain name and an IP address?

### **Module 3: The Two Sides of the Coin (Clients & Servers)**

- **Core Question Answered:** "What is a 'server' and how is it different from my computer?"
- **Concepts:** Defining a client (your browser, your phone app) as the one _requesting_ information. Defining a server as a powerful computer that is always on, _serving_ information.
- **Key Analogy:** A library. The client is you, the reader, who walks in and asks the librarian for a specific book. The server is the library itself, which stores all the books and has a librarian ready to find and deliver them to you.
- **Difficulty:** Easy
- **Importance Score:** 9/10
- **Questions to Answer:**
  - When you use your web browser to visit a website, is your browser acting as a client or a server?
  - What are the two main jobs of a web server?
  - In the library analogy, who is the client and who is the server?

### **Module 4: The Language of the Web (HTTP/HTTPS)**

- **Core Question Answered:** "How does my browser actually _ask_ for a website?"
- **Concepts:** HTTP as the protocol or set of rules for communication. The request-response cycle (client asks, server answers). Introduction to HTTPS as the secure version.
- **Key Analogy:** HTTP is like a waiter in a restaurant. You (the client) give the waiter a specific order (the request). The waiter goes to the kitchen (the server) and brings back what you asked for (the response).
- **Difficulty:** Easy
- **Importance Score:** 10/10
- **Questions to Answer:**
  - What is the job of the HTTP protocol?
  - What is the difference between an HTTP request and an HTTP response?
  - Why is it important to use websites with `https` when you are entering a password or credit card information?

### **Module 5: The Internet's Phonebook (DNS)**

- **Core Question Answered:** "How does my computer know that `google.com` means `142.250.184.174`?"
- **Concepts:** The role of the Domain Name System (DNS). The process of a DNS lookup.
- **Key Analogy:** DNS is the internet's giant, super-fast phonebook. When you type `akood.com` (a name), your browser asks the DNS server, "What's the phone number (IP address) for Akood?"
- **Difficulty:** Easy
- **Importance Score:** 10/10
- **Questions to Answer:**
  - What fundamental problem does the DNS solve?
  - In the process of loading a website, what happens right before the HTTP request is sent?
  - Using the phonebook analogy, explain the job of a DNS server.

### **Module 6: Building Blocks of a Webpage (HTML, CSS, JS)**

- **Core Question Answered:** "What is the code that the server sends back to my browser?"
- **Concepts:** A high-level, non-coding introduction to the three core web technologies. HTML as structure, CSS as presentation, and JavaScript as behavior.
- **Key Analogy:** Building a person. HTML is the skeleton (the structure). CSS is the clothes and appearance (the style). JavaScript is the personality and actions (the behavior).
- **Difficulty:** Easy
- **Importance Score:** 8/10 (Crucial context for future web dev tracks)
- **Questions to Answer:**
  - What are the three main technologies a browser uses to display a modern webpage?
  - If a webpage was a house, which technology would be the blueprint and foundation (HTML), the paint and furniture (CSS), and the electricity and plumbing (JavaScript)?
  - Which technology is responsible for what happens when you click a button on a website?

### **Module 7: Putting It All Together**

- **Core Question Answered:** "Can we walk through one full example from start to finish?"
- **Concepts:** A step-by-step review of the entire process, combining all previous modules.
- **Journey:** A review of the full request-response cycle from typing a URL to rendering the page.
- **Difficulty:** Easy
- **Importance Score:** 10/10 (Ties everything together)
- **Questions to Answer:**
  - Can you list the 5 main steps that happen between you typing a domain name and seeing the website?
  - What is the first thing your browser does after you press Enter on a URL?
  - Who sends the HTTP request, and who sends the HTTP response?
